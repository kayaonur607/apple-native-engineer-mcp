# Open-source portfolio workflow

This project is one part of Onur Kaya's free, open-source developer portfolio. Future projects and skills should each solve a concrete problem, document their scope and remain independently usable.

## A repeatable release checklist

1. Write the problem, intended user and one observable success condition.
2. Build the smallest working path, then demonstrate it using a reproducible example.
3. Add appropriate regression tests, a license, security notes and contribution instructions.
4. Write a README covering setup, examples, limitations, evidence and maintenance status.
5. Publish meaningful commits as work progresses. Explain the intent; avoid empty commits or artificial activity.
6. Publish versioned release notes and respond to real issues. Mark experimental, maintained and archived projects accurately.
7. Link complementary projects from the profile or repository documentation when they exist. Do not advertise unbuilt skills as shipped.

## Skill quality gate

A reusable skill needs clear triggers, bounded instructions, supported environments, safe defaults, an actual invocation example and a way to verify its outcome. Keep secrets and personal paths out of fixtures. Test the skill in a fresh environment before calling it stable.

## Community feedback

Use public minimal reproductions. Label bugs, documentation, false positives and enhancements consistently. A contributor should be able to reproduce a report from its version and command without a private conversation. Use a changelog to make genuine progress visible over time.

All current functionality is free under MIT. The AI client's own model requirements are separate. Customer adoption, download counts and accuracy metrics must come from actual measurements.
