# Visual identity and repository covers

## Default visual direction

Onur Kaya's open-source repositories share a restrained editorial technology style:

| Token | Value | Use |
| --- | --- | --- |
| Midnight navy | `#0B1018` | Main background |
| Mint | `#75E0BD` | Primary accent and fine lighting |
| Off-white | `#EDF3FB` | Title |
| Slate | `#A2B1C6` | Secondary text |

Use generous negative space, large legible left-aligned sans-serif type, subtle diagonal lines, thin flowing signals and restrained translucent layered geometry to the right. Keep the composition quiet and professional. Use wide landscape covers around 2.6:1 with safe text margins. Match the direction across future repository assets while adapting the title and subject to each actual project.

## Reusable generation brief

Create a wide GitHub repository cover in midnight navy, mint, off-white and slate. Place the exact project title and a short factual subtitle on the left, with generous negative space. Add subtle diagonal architectural lines, fine flowing signals and layered translucent geometry on the right. Use professional editorial typography. No standalone logo, Apple mark, mascot, fake UI, fabricated metrics or watermarks. Use a free/open-source label only when supported by the project's actual license and distribution terms.

## Evidence and accessibility

Keep generated decorative artwork separate from real execution captures. Provide descriptive alt text and restate essential product information in Markdown so it remains accessible and searchable. Never describe a static audit as App Store approval or runtime accessibility certification. Preserve actual test counts in documentation and generated evidence.
